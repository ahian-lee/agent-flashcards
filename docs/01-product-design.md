# Agent 闪卡 · 产品与内容设计

> 版本：v1.0（2026-10-26）  
> 定位：用「背单词」的心智模型，把 Agent 知识拆成可每日复习的原子卡片。  
> 配套文档：[GitHub 调研](research/github-repos.md) · [架构设计](02-architecture.md) · [开发计划](03-dev-plan.md)

## 1. 产品定位

### 1.1 一句话

**每天 10 分钟，像背单词一样把 Agent 知识背进长期记忆。**

### 1.2 要解决的问题

Agent 知识（基础概念、面试题、后训练）有三个特征：

1. **概念密集且互相引用**：ReAct、工具调用、记忆、RAG、多 Agent、SFT/RLHF/DPO 彼此关联，通读长文容易「看懂了但记不住」；
2. **面试/工作场景要求「脱口而出」**：需要的是可检索、可复述的结构化记忆，而不是收藏夹里的文章；
3. **碎片时间为主**：目标用户（Agent 学习者、面试者、转型中的工程师）主要在通勤、排队、睡前用手机学习。

现有方案要么是长文课程（完课率低）、要么是 Anki（学习曲线陡、内容与移动端体验不匹配）、要么是零散笔记（没有复习机制）。本产品把「内容原子化 + 间隔重复 + 移动端优先」三者结合。

### 1.3 目标用户

| 用户 | 场景 | 核心诉求 |
| --- | --- | --- |
| Agent 初学者 | 碎片时间入门 | 体系化、不迷路、每天有进度感 |
| 面试准备者 | 面试前 1–4 周 | 高频题、结构化答案、可自测 |
| 算法/后训练工程师 | 补齐概念与术语 | 准确、有出处、可深挖 |
| 团队新人 | onboarding | 统一知识基线、可分享牌组 |

### 1.4 非目标（V1 不做）

- 不做社区/UGC 内容平台、不做排行榜与社交攀比；
- 不做 AI 自动出题（V2 可做「AI 拆卡」辅助，但人工审核）；
- 不做课程视频/长文阅读器；
- 不做服务端账号体系（V1 本地优先，导出/导入兜底；同步见架构文档 Phase 2）。

### 1.5 差异化

| 维度 | Anki | 通用背单词 App | 本产品 |
| --- | --- | --- | --- |
| 内容 | 用户自建/共享牌组 | 英语词库 | Agent 垂直题库，按「知识书」组织 |
| 移动端 | AnkiDroid/AnkiMobile 可用但偏工具 | 好 | PWA 即开即用、可安装、离线 |
| 复习算法 | FSRS/SM-2（强） | 多为 SM-2 | FSRS-6（复用 ts-fsrs） |
| 面试场景 | 无专门模式 | 无 | 面试 deck + 结构化答案 + 追问标签 |
| 数据 | 本地/AnkiWeb | 账号云 | 本地优先 + JSON 导入导出，可互操作 Anki |

## 2. 核心体验闭环

```
打开 App
  ↓
首页看到「今天还有 N 张」（到期复习优先，其次新卡）
  ↓
点「开始学习」→ 卡片正面（问题）
  ↓
回忆 → 翻面看答案 → 自评（忘了 / 困难 / 记得 / 太简单）
  ↓
FSRS 计算下次复习时间 → 写入本地
  ↓
队列耗尽 → 会话小结（学了几张、正确率、明天还有几张）
  ↓
连续天数 +1（当天首次完成学习）
```

设计原则：

1. **一次只做一件事**：学习页全屏卡片，无导航干扰；
2. **回忆优先**：先想再翻面，翻面前不显示答案；
3. **诚实自评**：四档评分对应 FSRS 四档，文案用「记得/忘了」而非「对/错」；
4. **低摩擦**：单手可完成（拇指区按钮），无登录、无网络依赖；
5. **可解释**：每张卡展示「下次复习：X 天后」，让用户感知算法在工作。

## 3. 平台策略与三端互通

### 3.1 结论

**V1 用响应式 PWA（React + Vite）覆盖手机浏览器 / 可安装到主屏 / 桌面浏览器；域逻辑（内容、FSRS、队列、存储接口）与 UI 解耦，为微信小程序（Taro）和原生壳预留。**

### 3.2 方案对比

| 方案 | 覆盖 | 开发成本 | 复用性 | 风险 |
| --- | --- | --- | --- | --- |
| **PWA（推荐 V1）** | iOS Safari、Android Chrome、桌面浏览器；可安装 | 低（一套 Web） | 高：内容/算法/存储纯 TS | iOS 推送/后台受限；微信内分享体验一般 |
| 微信小程序（Taro/uni-app） | 微信生态 | 中（需适配 UI、存储、无 DOM） | 中：可复用纯 TS 域逻辑，UI/存储需重写 | 审核、包体限制、无 IndexedDB |
| React Native / Flutter | App Store / 应用商店 | 高 | 低：需重写 UI，算法可复用 | 双端适配、发版审核 |
| 纯网页（非 PWA） | 浏览器 | 最低 | 高 | 不可安装、离线弱 |

### 3.3 三端落地路径

- **现在**：PWA。手机浏览器打开即用；iOS「添加到主屏幕」、Android「安装应用」；桌面端居中布局。
- **Phase 2（有微信分发需求时）**：Taro 4（React 语法）复用 `app/src/lib`（scheduler、queue、content 校验、stats），实现小程序页面；存储换成 `wx.setStorage`/云开发；内容包随小程序发布。
- **Phase 3（可选）**：Capacitor 套壳上架（复用 PWA 代码），或 Taro RN 输出原生 App。

### 3.4 多端数据互通

- V1：本地 IndexedDB；「导出 JSON / 导入 JSON」跨设备迁移（AirDrop、微信文件、网盘均可）。
- Phase 2：账号 + 同步服务（Supabase / Cloudflare D1），按卡片粒度 LWW + 复习日志 append-only，详见架构文档 §8。

## 4. 信息架构与页面

### 4.1 页面树

```
/                    首页（今日进度 + 牌组列表）
/study/:deckId?      学习会话（全屏）
/stats               统计

底部 Tab：**学习 · 统计 · 设置**（学习页内隐藏 Tab，避免误触）。

### 4.2 首页

│ Agent 闪卡            ⚙️     │
│  今日 12 / 20      🔥 连续 6 天 │
│  ▓▓▓▓▓▓░░░░  60%             │
│                              │
│  [ 开始学习（12 张） ]        │
│                              │
│  牌组                         │
│  ┌────────────────────────┐  │
│  │ Agent 基础知识          │  │
│  │ 新卡 8 · 到期 3 · 已掌握 12/28 │
│  │ ▓▓▓▓▓░░░░░ 44%          │  │
│  └────────────────────────┘  │
│  ┌────────────────────────┐  │
│  │ Agent 面试题库          │  │
│  └────────────────────────┘  │
│  ┌────────────────────────┐  │
│  │ Agent 后训练知识        │  │
│  └────────────────────────┘  │
│                              │
│  [学习]   [统计]   [设置]     │
└──────────────────────────────┘
```

- 今日进度 = 今日已评价卡数 / 每日目标；目标由「新卡上限 + min(到期复习数, 复习上限)」派生，不单独设置；
- 牌组卡显示新卡数、到期数、已掌握/总数、进度条；
- 点击牌组进入该 deck 会话；点主按钮进入混合队列（到期优先）；
- 连续天数：本地日界（设备时区）连续有复习记录的天数。

### 4.3 学习页

**QA 卡**

```
┌──────────────────────────────┐
│ ←   Agent 基础知识      3/12 │
│ ▓▓▓░░░░░░░░░░░░░░░░░░        │
│                              │
│  什么是 ReAct？               │
│                              │
│  [ 点击查看答案 ]             │
│                              │
│  （翻面后）                   │
│  Reasoning + Acting：让模型   │
│  交替产生推理与动作……         │
│                              │
│  下次复习：3 天后             │
│  [忘了][困难][记得][太简单]   │
└──────────────────────────────┘
```

**MCQ 卡**：4 个选项，点选后立即判定（绿/红），显示解析，再进入四档自评（默认答对=记得、答错=忘了，可改）。

**Cloze 卡**：`{{c1::…}}` 渲染为挖空按钮，点击揭示；全部揭示后翻面显示完整答案并自评。

交互细节：

- 点击卡面 / 空格 = 翻面；键盘 1–4 = 四档评分（桌面）；
- 评分按钮 ≥ 56px 高，底部安全区留白；
- 评分后卡片左滑出、下一张淡入（尊重 `prefers-reduced-motion`）；
- 顶部进度条按「本次会话总卡数」推进；
- 学习页显示「剩余 N 张」，队列空 → 会话小结。

### 4.4 统计页

- 概览：总卡数、已掌握、今日已复习、今日到期；
- 近 7 天复习量柱状图（按本地日界）；
- 每 deck 进度条与准确率（Good+Easy / 总评分）；
- 连续天数、累计复习次数。

### 4.5 设置页

| 分组 | 项 | 默认 | 说明 |
| --- | --- | --- | --- |
| 学习 | 每日新卡上限 | 20 | 全局；控制学习负担 |
| 学习 | 每日复习上限 | 200 | 防止积压爆炸 |
| 学习 | Learn-ahead 窗口 | 20 分钟 | 学习中的卡提前拉回本次会话 |
| 外观 | 主题 | auto | auto/light/dark |
| 数据 | 导出 JSON | - | 全量状态 + 日志 + 设置 |
| 数据 | 导入 JSON | - | 校验 schema/版本后按 cardId 合并 |
| 数据 | 重置进度 | - | 二次确认，仅清状态不删内容 |
| 关于 | 算法说明 | - | FSRS-6、评分含义、隐私声明 |

## 5. 内容体系

### 5.1 组织方式

```
知识书（Collection）
  └── 牌组（Deck）：agent-basics / agent-interview / agent-post-training
        └── 卡片（Card）：qa / mcq / cloze
              └── 标签（Tags）：用于筛选与 V2 智能组卷
```

每个 deck 是一本「知识书」，卡片按主题标签组织；V1 先做三本：

| Deck | 定位 | 卡数 | 典型标签 |
| --- | --- | --- | --- |
| `agent-basics` | Agent 基础知识 | 28 | Agent Loop、ReAct、工具调用、MCP、记忆、RAG、多 Agent、护栏、评估 |
| `agent-interview` | 面试题库 | 28 | 系统设计、评估、降幻觉、上下文、安全、可观测性 |
| `agent-post-training` | 后训练知识 | 28 | SFT、RLHF、PPO、DPO、GRPO、LoRA、蒸馏、评测 |

### 5.2 卡片原子化原则（内容质量的硬约束）

1. **一张卡一个知识点**：能拆就拆。例：「ReAct 是什么 + 优缺点 + 与 Plan-and-Execute 区别」应拆成 2–3 张；
2. **最小信息原则**：答案不写整段论文，写 2–4 个要点，每点 1–2 行；
3. **可自测**：问题必须能在不翻面的情况下明确知道「要回忆什么」；
4. **答案可判分**：用户能判断自己「记得/不记得」，避免开放到无法自评；
5. **有出处**：`source` 字段填写论文/官方文档，便于复核与深挖；
6. **稳定 ID**：`deckId-cardId` 一经发布不复用；下线卡片保留 ID 并标记退役，避免用户进度错位；
7. **面向手机**：问题 ≤ 60 字，答案 ≤ 250 字（面试题可到 400 字）；代码块 ≤ 10 行。

### 5.3 卡型选择指南

| 场景 | 卡型 | 例子 |
| --- | --- | --- |
| 概念定义、原理、对比 | `qa` | 「ReAct 的核心思想是什么？」 |
| 易混淆的并列概念 | `mcq` | 「以下哪项不是 MCP 的三大原语？」 |
| 术语、公式、流程步骤 | `cloze` | 「DPO 的损失函数中，β 控制 {{c1::与参考模型的偏离程度}}」 |
| 面试系统设计 | `qa`（结构化答案） | 「如何设计一个客服 Agent？请给出架构与评估方案」 |

比例目标：qa ≈ 70%，mcq ≈ 20%，cloze ≈ 10%。

### 5.4 三本知识书的选题覆盖

**agent-basics（28）**

1. LLM Agent 的定义与目标；2. 四大组件；3. Agent loop；4. ReAct；5. Plan-and-Execute 与 ReAct 对比；6. CoT/ToT；7. Function Calling 流程；8. 工具 schema 设计；9. 工具失败处理；10. MCP 是什么；11. MCP 三大原语；12. 记忆分层；13. 长期记忆写入与检索；14. RAG 链路；15. RAG + Agent；16. 上下文管理；17. 多 Agent 编排模式；18. 多 Agent 通信；19. 护栏分层；20. HITL；21. Agent 评估指标；22. LLM-as-judge；23. 可观测性；24. 失败模式：循环；25. 失败模式：工具误用；26. 成本优化；27. 延迟优化；28. Prompt injection；29. Agent 与 Workflow 的边界。

**agent-interview（28）**

系统设计：客服 Agent、代码 Agent、研究 Agent；工程实践：工具不稳定排查、评估体系、降幻觉、长上下文、多 Agent 通信、线上事故排查、安全防护、权限审批、记忆系统、RAG 召回评估、成本、延迟、灰度/A-B、HITL、澄清、重试幂等、回归测试集、模型选型、流式与中断、配置化、工具描述质量、隐私删除、注入攻击、Agent 与 RAG 组合、计费、可观测性。

**agent-post-training（28）**

### 5.5 内容生产管线

```
选题表（§5.4）
  → 写作（人/AI 辅助，必须给 source）
  → JSON 结构校验（schema、id 唯一、mcq 选项、cloze 标记）
  → 内容抽检（事实/表述/难度）
  → 同步到 app（scripts/sync-content.mjs）
  → 构建发布（内容随包，离线可用）
  → 版本化（deck.version + updatedAt；数据库按 cardId 迁移）
```

### 5.6 与 Anki 的互操作

- **导入**（V2）：支持 Anki 导出的 TSV（Front/Back/Tags）映射为 `qa`；APKG 解析成本高（SQLite + 媒体），V2 评估。
- **导出**（V2）：把 deck 导出为 Anki TSV（Front=question，Back=answer+explanation，Tags=tags），用户可在 Anki 继续复习。
- 本产品 JSON 为 canonical 格式，Anki 仅作为互操作出口，避免双向同步的复杂度。

## 6. 学习流程与记忆机制（产品口径）

### 6.1 每日流程

1. 打开首页 → 看到今日队列计数；
2. 开始学习 → 到期复习卡优先（due ≤ now），其次新卡（受每日上限约束）；
3. 每张卡：回忆 → 翻面 → 四档自评 → FSRS 安排下次；
4. 学习中的卡（Learning/Relearning）若在 20 分钟内到期，队列末尾提前拉回（learn-ahead）；
5. 队列空 → 会话小结：本次学习 N 张、正确率、下次到期时间；
6. 当天首次完成 → 连续天数 +1。

### 6.2 评分语义（与 FSRS 对齐）

| UI 文案 | FSRS Rating | 用户理解 | 典型效果 |
| --- | --- | --- | --- |
| 忘了 | Again (1) | 完全没想起来 | 几分钟后重来 |
| 困难 | Hard (2) | 想起来了但很吃力 | 较短间隔 |
| 记得 | Good (3) | 正常回忆 | 标准间隔 |
| 太简单 | Easy (4) | 秒答 | 更长间隔 |

- MCQ：答对默认预选「记得」，答错默认预选「忘了」，用户可改；
- Cloze：揭示后自评，不自动判分。

### 6.3 每日上限与积压

- 新卡上限（默认 20/天）按「当天首次评价的新卡数」计数；
- 复习上限（默认 200/天）按「当天评价的非新卡数」计数；
- 超出上限的到期卡保留到期状态，次日继续；首页明确显示「积压 N 张」，避免隐藏负担；
- 连续多天未学：不惩罚，按到期顺序消化；可提示「先做 20 张」拆解。

### 6.4 掌握与 leech

- **已掌握**（展示口径）：状态为 Review 且 `reps ≥ 3` 或 `stability ≥ 21 天`（约 3 周），仅用于进度展示，不参与调度；
- **Leech**：同一卡累计 `lapses ≥ 4` 时标记「难点」，在卡片与统计中提示；V1 不自动暂停（避免用户困惑），V2 提供「暂停/改写卡片」；
- 不提供手动「已掌握」按钮，避免污染调度数据；提供「暂停卡」（V2）。

### 6.5 复习提醒

- V1：PWA 内提醒（打开时显示今日到期）；不做系统推送（iOS PWA 推送限制多）。
- V2：Web Push（Android/桌面）+ 本地通知（Capacitor 壳），或邮件/微信服务号提醒。

## 7. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 首屏（4G）< 2s；学习页切换 < 100ms；构建产物 JS < 500KB gzip |
| 离线 | 首次访问后完全离线可用（内容随包 + SW 缓存）；无网络时评分照常写入 |
| 兼容 | iOS Safari 16+、Android Chrome 110+、桌面 Chrome/Edge/Safari 最新两个大版本 |
| 可访问性 | 对比度 ≥ 4.5:1；触摸目标 ≥ 44px；键盘可完成全流程；`prefers-reduced-motion` |
| 隐私 | 无账号、无埋点上报；所有数据仅存本地；导出/删除由用户掌控 |
| 安全 | 导入 JSON 严格校验（类型/大小/字段白名单）；Markdown 仅渲染白名单子集，禁止原始 HTML |
| 可靠性 | IndexedDB 写失败有提示；SW 采用 autoUpdate（下次加载接管）；导出文件带 version 与导出时间 |
| 国际化 | V1 中文；文案集中管理，预留 i18n（V2） |

## 10. 关键文案与边界情况

- 空态：首页「今天没有到期卡片，去学几张新卡吧」；学习页「本 deck 已学完，明天再来」；
- 首次使用：默认每日新卡上限 20，首页解释「FSRS 会在你快忘记时安排复习」；今日目标由新卡上限与到期复习数派生；
- 导入失败：明确原因（文件格式/版本/字段错误），不覆盖现有数据；
- 重置：需输入「重置」或二次确认，提示可先导出备份；
- 跨天学习：会话跨过本地 0 点，评分按实际发生时间计入当天，进度环按当前日界刷新；
- 时钟回拨：若 `now < last_review`，按 `now` 调度并在日志标记 `clock_skew`，不崩溃；
- 存储被清理：启动检测 IndexedDB 为空但用户曾导入 → 提示「本地数据可能被清理，可导入备份」；
- 多标签页同时学习：Dexie 实时同步 + 每次评分前读最新状态，冲突以最后一次评分为准（V1 单设备假设）。
